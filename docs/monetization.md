# 収益化方針

## 1. 原則

収益より「快適にアニソンを探せること」を優先する。どの収益手段も、検索・リスト作成・聴くまでの流れを妨げない形でのみ導入する。

## 2. 優先順位

| 順 | 手段 | 状態 | 着手条件 |
|---:|---|---|---|
| 1 | **広告（表示・クリック型）** | 有効化済み・**配信なし**（AdSense。2026-10-17 時点で 1 件も表示されていない。[ads.md](ads.md#9-現在の配信状況2026-10-17-に本番で確認)） | 配信されない原因の解消 |
| 2 | プレミアム会員（月額） | 判定の器のみ | 継続利用者が一定数いること・決済基盤 |
| 3 | アフィリエイト（CD・Blu-ray・グッズ） | 未着手 | 曲・アニメ詳細の「購入」導線の設計 |
| 4 | ライブ・イベント送客 | 未着手 | イベント情報の取得元の確保 |
| 5 | スポンサータイアップ | 未着手 | 媒体としての利用者数・実績 |

### なぜ広告が最優先か

- 利用者が少ない段階でも、追加の開発なしで収益の受け皿を用意できる
- AdSense は審査に日数がかかる。早めに審査を通しておけば、利用者が増えた時点ですぐ収益化できる
- 基盤はプロバイダを差し替えられる作りにしてあるため、将来ネットワークを変えても画面側の改修が要らない

## 3. 各手段の設計メモ

### 3.1 広告

仕様は [ads.md](ads.md)。密度を低く保ち、現状はディスプレイ 3 か所（ホーム・曲詳細・アニメ詳細）と検索結果のインフィード。ネイティブアプリ版では AdMob を追加する（ストア公開後）。

### 3.2 プレミアム会員

| 項目 | 方針 |
|---|---|
| 特典 | 広告の全非表示。将来は AI レコメンド・詳細検索・統計（聴いた傾向の分析）を追加 |
| 決済 | Web は Stripe、ネイティブアプリはアプリ内課金（Apple / Google の規約でデジタル特典はアプリ内課金が必要） |
| 判定 | 現在は開発用の localStorage フラグ。決済導入時に DB / 課金基盤の値で判定し、クライアントの値は信用しない |

### 3.3 アフィリエイト（CD・Blu-ray・グッズ）

曲詳細・アニメ詳細に「CD / Blu-ray / グッズを探す」導線を置く。広告と違いユーザーが自分から押すものなので、体験を損ないにくい。リンク先・提携プログラムは未選定。

### 3.4 ライブ・イベント送客

アーティスト詳細に出演予定のライブ・イベントを表示し、チケット販売サイトへ送客する。イベント情報の取得元（API や提携）の確保が前提。

### 3.5 スポンサータイアップ

レーベル・作品とのタイアップ（新曲の特集枠、リスト企画など）。利用者数と実績ができてからの営業になる。
