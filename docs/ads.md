# 広告システム仕様

## 1. 方針

**最優先は広告収益ではなく「快適にアニソンを探せること」。** 広告はコンテンツの邪魔をせず、密度を低く保つ。「広告が少なくて使いやすい」と感じてもらうことを目標にする。

### 採用する広告

- ネイティブ広告
- インフィード広告
- バナー広告（必要最低限）

### 採用しない広告

| 種類 | 理由 |
|---|---|
| インタースティシャル（全画面）広告 | 操作を中断させる |
| 強制動画広告 | 音楽体験を妨げる |
| リワード広告 | 閲覧の対価に広告視聴を求める設計は方針に合わない |
| 画面遷移ごとの広告・閉じるまで操作できない広告 | 同上 |

## 2. 配置

### 目標の配置（正式仕様）

| 画面 | 配置 |
|---|---|
| ホーム | おすすめ → **広告** → ランキング |
| 曲詳細 | レビュー → **広告** → 関連曲 |
| アニメ詳細 | 挿入歌一覧 → **広告** → レビュー |
| 検索結果 | 5 件ごとに 1 枠 |

共通ルール：再生ボタン（YouTube / 各サービスへの導線）の近くには置かない。スクロール開始直後には出さない（現状この「見えてから表示」が効いているのはホームの枠だけ）。

### 現在の実装との差

| 画面 | 現在の実装 | 目標との差 | 対応 |
|---|---|---|---|
| ホーム | ページ末尾に 1 枠（検索結果とページ送りのさらに下。スクロールして見えてから表示）。検索後はこれとインフィードで計 2 枠になる | 「おすすめ」「ランキング」セクションがまだ無い | セクション実装時に間へ移す |
| 曲詳細 | ページ末尾に 1 枠 | 「レビュー」「関連曲」がまだ無い | セクション実装時に間へ移す |
| アニメ詳細 | 作品情報の直後・**曲一覧の上** | 目標は曲一覧の**下**。今すぐ直せる | Issue 化（[ROADMAP](../ROADMAP.md)） |
| 検索結果 | 5 件ごとにインフィード 1 枠 | 設定は一致。ただし 1 ページ 10 件で最後の行の直後には出さないため、**実質 1 ページ 1 枠**（5 件目の後のみ）。リストへ曲を追加する画面（ピッカー）では出さない | — |
| ランキング | 設定のみ（4 件ごと） | ランキングページ自体が無い。AdSense のユニット ID も未設定（`adsenseSlot: null`） | ページ実装時にユニットを作って設定する |

**なぜ現状がこうなっているか**：2026-07-07 に受け取った最初の仕様が、まだ存在しない画面セクションを前提にしていた。そこで広告の「仕組み」を先に作り、今ある場所にだけ配置し、未実装セクション向けの枠は設定に予約した。

## 3. プレミアム会員

会員は**すべての広告を非表示**にする。広告枠は会員判定が真なら何も描画しない（空白も残さない）。

将来、AI レコメンド・詳細検索・統計（再生履歴分析）などの特典を追加できるよう、判定は `useEntitlement()` に集約している。

**現状は判定の器のみ**。`localStorage` の `soniclist:premium` を見る開発用の実装で、決済は無い。決済導入時に、DB またはアプリ内課金基盤の判定へ置き換える（クライアントの値は誰でも書き換えられるため）。

## 4. 技術設計

```
ページ ── <AdSlot placement="search_infeed" />
            │  AdContext（設定・会員判定・同意・プロバイダを供給）
            ├─ getPlacement(config, placement)   有効か・形式・頻度
            ├─ 会員なら null / 同意なしなら null
            ├─ 高さ固定の枠 + スケルトン（CLS 対策）
            └─ provider.renderSlot(...)
                 ├─ placeholderProvider  → 電光掲示板デザインのダミー（開発用）
                 ├─ adsenseProvider      → <ins class="adsbygoogle">
                 └─ admobProvider（未実装・Capacitor 公開後）
```

ページは広告 SDK を一切知らない。差し替えはプロバイダの追加と設定の変更だけで済む。

| 要求 | 状態 | 実装・方針 |
|---|---|---|
| Provider 抽象化 | ✅ 実装済み | `lib/ads/providers/` の各プロバイダが `renderSlot()` を持つ |
| Adapter パターン | ✅ 実装済み | `getProvider(name)` が設定名から実体を返す |
| DI | 🔶 一部 | `AdContext` が設定・プロバイダ・会員判定・同意を注入し、ページは `<AdSlot>` を置くだけ（`useAds()` を呼ぶのは広告コンポーネントのみ）。ただし `adsenseProvider` は `AD_CONFIG` を直接 import してユニット ID を読んでおり、注入された設定を使っていない |
| Remote Config | ⬜ 未実装 | 現在は `adConfig.js` の静的設定 + ビルド時の環境変数。リモート化するには、`AdContext` が取得した設定を供給するよう変え、`adsenseProvider` の `AD_CONFIG` 直接参照も外す必要がある（ページ側は変更不要） |
| Analytics | 🔶 一部 | 表示（impression）は、ホームの枠は画面に入った時点、それ以外は枠のマウント時に送信。送り先は `setAdSink()` で差し替え可能だが、現状は開発時のコンソール出力のみ。AdSense のクリックは iframe 内のため検知できず、クリック数・CTR は AdSense のレポートで見る |
| A/B テスト | ⬜ 未実装 | 配置・頻度・形式を設定値に寄せてあるので、ユーザー単位で設定の版を切り替える仕組みを足せば実施できる |
| 同意管理（CMP） | 🔶 一部 | AdSense 側で Google 認定 CMP（同意する / 同意しない / オプション管理の 3 択）を設定済み。アプリ内の `consent.js` は既定で許可を返す受け皿のみ |
| レイアウトずれ防止 | ✅ 実装済み | 形式ごとに高さ固定（ネイティブ 250px / インフィード 150px / バナー 90px）、はみ出しは隠す |

## 5. 広告カテゴリ

アニメ・アニソン・音楽配信・CD・Blu-ray・フィギュア・ゲーム・ライブ・イベント・オーディオ機器・イヤホン・ヘッドホンを優先し、無関係な広告は極力出さない。

優先カテゴリは `AD_CATEGORIES` に定義済みだが、**AdSense は配信ごとにカテゴリを指定できない**。実際の絞り込みは AdSense 管理画面の「広告の許可とブロック」で行う（設定状況は未確認）。将来、カテゴリ指定に対応したネットワークを足す場合はこの値をプロバイダに渡す。

## 6. デザイン

サイト全体のサイバーパンク調に合わせ、開発用ダミーは「電光掲示板」風の枠（脈打つネオン・走査線・黄色の「広告」ラベル・流れる文字）で作った。

規約上、**広告そのもの（iframe 内の creative）に効果をかけるのは不可**（誤クリック誘発とみなされ、技術的にも iframe 内には届かない）。枠の外側の装飾は可。現在の AdSense 実装は枠で囲んでおらず、「広告」ラベルも付けていない。未配信時は何も見えない空白になる（課題）。

## 7. 運用

| 操作 | 方法 |
|---|---|
| 本番で広告を出す / 止める | Netlify の環境変数 `REACT_APP_ADS_ENABLED=true` と `REACT_APP_ADS_PROVIDER=adsense` を設定して再ビルド。止めるときは `REACT_APP_ADS_ENABLED=false`（未設定にすると端末の `ads-preview` フラグが効いてしまう） |
| プロバイダの切り替え | `REACT_APP_ADS_PROVIDER`（`adsense` / `placeholder`） |
| 開発中に見た目を確認 | `localStorage.setItem('soniclist:ads-preview','true')` |
| 会員表示の確認 | `localStorage.setItem('soniclist:premium','true')` |

## 9. 現在の配信状況（2026-10-17 に本番で確認）

| 枠 | 状態 |
|---|---|
| 検索結果（インフィード `6207135488`） | 広告リクエストは出ているが、毎回 `unfilled`（在庫なし） |
| 曲詳細（ディスプレイ `1984406755`） | スクリプトは処理済みだが、広告の iframe が作られていない（リクエスト自体が出ていない可能性） |
| ページ単位の要素 | どのページにも、こちらで置いていない AdSense の要素（`<body>` 直下・ユニット ID なし）が自動で差し込まれている。**アカウント側で自動広告が有効**とみられる |

立ち上がり待ちでは説明がつかない期間が経っているため、次を確認する。

1. 👤 AdSense 管理画面の「サイト」で `soniclist.app` の状態が「準備完了」か。ポリシー違反・アカウント保留の通知が無いか
2. 👤 自動広告が ON なら **OFF にする**（少なくとも全画面の「モバイル全画面広告（vignette）」とアンカー広告）。全画面広告は本仕様で不採用としている
3. ディスプレイ枠：`<ins>` に `height: 100%` を指定しているため、レスポンシブ広告が幅・高さを判定できていない可能性がある。高さ指定を外し、外側の枠だけで高さを確保する形を試す
4. 1〜3 を直しても在庫が付かない場合は、アクセス数が少ないことが原因の可能性が高い
